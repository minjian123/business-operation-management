1. 目的与定义

本文档是 biz 运营体系交互式界面原型体系的总览。本体系中的「原型」指可在浏览器中直接点击操作的交互原型： 每个界面为独立的 HTML 文件（双击即开、file:// 可用），可点击按钮、切换 Tab、打开弹窗、录入表单、跳转视图， 达到「像真实系统一样操作」的程度。每个模块一个子文件夹，内含一份模块设计说明（总览该模块全部界面与交互要点）与若干 可交互界面原型文件。

与静态线框图的区别：本体系原型带真实交互（JS 驱动），可直接演示与评审，不需要阅读想象力。
平台机制界面（登录、主框架、用户/角色/菜单管理、租户管理等）属 bms 平台，见 bms 仓库《原型设计 · 总览》；本体系只覆盖 biz 企业运营业务界面。

2. 目录结构

biz文档/设计/原型设计/
├── 01_原型设计_总览.html          ← 本文件（体系导航）
├── 共享资源/
│   ├── vendor/                    ← 本地化组件库（vue.global.prod.js / element-plus.min.js+css / vant.min.js+css）
│   └── 原型样式.css               ← 公共框架样式（proto-bar / proto-frame / proto-hint 等）
└── {NN}_{模块名}/                  ← 模块子文件夹（NN 为顺序编号，即阅读顺序）
    ├── 01_设计说明.html             ← 模块设计说明（界面清单 + 交互要点 + 引用各界面原型）
    ├── 02_{界面名}.html             ← 可交互界面原型（编号即界面阅读顺序，独立文件双击即开）
    └── ...
  • 模块文件夹命名：{两位编号}_{模块名}（如 02_采购、03_收付款），编号即阅读顺序；总览为 01 不建文件夹
  • 模块内文件命名：{两位编号}_{文件名}——设计说明固定为 01_设计说明.html，界面按阅读顺序 02 起编号
  • 产品体系编号独立于 bms 从 01 起，与平台原型体系平行；跨体系引用只写文档名，不复制平台原型
  • 界面原型使用真实组件库（与正式开发技术栈一致）：PC 端 Element Plus、移动端 Vant，本地化引入（共享资源/vendor/），file:// 双击即用；框架样式引用 <link rel="stylesheet" href="../共享资源/原型样式.css">
  • 共享资源/为原型公共资源，从 bms 仓库 bms文档/设计/原型设计/共享资源/ 复制（产品仓库自带一份，bms 侧更新时需手动对齐），并存放平台公共原型组件 04_系统信息组件.html（从 bms 复制、内部路径已本地化）；升级组件库版本时两处一并更新
  • 设计说明页列出该模块全部界面，逐条链接到可交互原型，并附交互要点与验收关注点

4. 交互原型规范

  • 可交互程度：按钮点击有反馈（弹窗/Toast/状态变化）、Tab 可切换、弹窗可开关、表单可录入、列表行可点击进入详情视图、危险操作有确认框——达到可直接演示的程度
  • 模拟数据：使用内置假数据（不依赖后端）；交互只做前端模拟，不做真实持久化
  • 公共组件：一律使用 共享资源/ 的按钮/表格/弹窗/表单/标签/Toast 组件，保证全体系风格一致；单界面私有样式内联 <style>
  • 原型条：每个界面顶部有原型条（返回设计说明 + 界面名），便于评审时跳转
  • 真实组件对齐：交互与视觉对齐 Element Plus / Vant 实际组件行为（原型即验收基准）
  • 可访问性：file:// 双击打开即可用，不依赖构建与联网

5. 与设计文档体系的关系

体系回答的问题形式归属
平台布局设计栅格/间距/组件形态的统一约定规范文档bms 平台
概要设计模块功能、流程、接口、权限设计定案biz 本仓库
原型设计（本体系）界面长什么样、点哪里去哪可交互演示biz 本仓库
  • 原型是需求确认与开发参照基准；视觉基线与交互框架沿用平台布局设计与原型规范（见平台《原型审查规范》）
  • 原型暴露的功能/流程问题 → 先修订概要设计，再同步原型

6. 评审与迭代流程

  1. 模块产出「设计说明 + 可交互原型」→ 直接点击演示评审（真实操作）
  2. 评审意见 → 修改对应界面原型（交互或布局）→ 设计说明同步「迭代记录」
  3. 定稿 → 设计说明标注「已确认」→ 开发按原型实现（原型即验收基准）
